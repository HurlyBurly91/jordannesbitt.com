# Canonical domain index

Load these documents selectively; this index is not a second execution ledger.

- `catalogue.md`: schema, relationships, publication and confidentiality boundaries.
- `design.md`: artwork-led presentation, curation and content intake.
- `acquisition.md`: availability, enquiries, editions, truthful offers and later checkout.
- `quality.md`: discovery, accessibility, performance and verification evidence.
- `verification-portfolio.md`: DSM 1.2.5 Tier 1/2 selectors, named Tier 3 qualifications, test lifecycle, oracle independence and cost review.
- `operations.md`: inspected baseline, local setup, agent runtime, permissions and release.
- `research.md`: dated evidence, earlier-brief reconstruction and derived design decisions.
- `studio.md`: private local authoring, preview, concurrency and export preparation behavior.

These describe required current project behavior unless explicitly labelled otherwise. Active execution belongs in `STATUS.md`/`TASKS.md`; retrospective provenance belongs in `records/`.

Generic schema/provenance rules are framework-owned at `.durable-state/framework/SCHEMAS.md`. Project canonical docs remain project-owned and are never replaced by framework updates.

Optional `sources/` and `data/research/` layers should be introduced only when retained external evidence/structured observations materially constrain implementation; do not fabricate them merely to match a template.

The experience layer is advisory and separate from canonical truth. See `experiences/SCHEMA.md`; experience never overrides current requirements/evidence and is not required for reconstruction.
